# ApiHub 企业微服务集成化接口平台

## 1. 项目概述

### 1.1 课题名称

基于 EasyAPI 思想的企业微服务集成化接口平台（ApiHub）设计与实现

### 1.2 项目背景

企业内部系统增多后，接口对接成本高、鉴权方式不统一、缺少调用审计与限流能力。本平台参考 EasyAPI / API 开放平台模式，提供统一接入、鉴权、文档、调用统计与日志追踪，降低系统集成成本。

### 1.3 建设目标

- 统一管理企业开放接口的注册、发布、下线
- 管理端使用 JWT 鉴权；开放调用使用 AppId + 签名鉴权
- 支持调用日志、TraceId 全链路追踪、基础限流与配额
- 自动生成接口文档，前后端分离部署
- 使用 Docker + Nginx 完成可演示的一键部署

### 1.4 技术栈

| 类别 | 技术 |
|------|------|
| 后端 | Spring Boot 多模块、微服务思想 |
| 数据库 | MySQL |
| 缓存 | Redis |
| 认证 | JWT（管理端）、HMAC 签名（开放调用） |
| 文档 | SpringDoc / Knife4j（OpenAPI） |
| 前端 | Vue3 或 React（`web-admin`） |
| 部署 | Docker Compose、Nginx |

## 2. 需求分析

### 2.1 用户角色

| 角色 | 说明 |
|------|------|
| 普通用户（USER） | 注册登录、创建应用、申请开通接口、查看本人调用日志与统计 |
| 管理员（ADMIN） | 发布/下线接口、管理用户与应用、查看全局统计 |
| 外部调用方 | 持有 AppId/Secret，通过签名调用已开通的开放接口 |

### 2.3 非功能需求

| 编号 | 类别 | 要求 |
|------|------|------|
| NF-01 | 安全 | 密码 BCrypt；JWT 有效期可控；签名防重放（时间窗 + Nonce） |
| NF-02 | 可观测 | 日志带 TraceId；关键调用可落库审计 |
| NF-03 | 性能 | 热门配置可缓存；网关限流保护下游 |
| NF-04 | 可维护 | 多模块拆分；统一返回体与错误码 |
| NF-05 | 可部署 | 本地与 Docker 均可演示；配置外置 |
| NF-06 | 兼容 | Java 17；前后端分离；浏览器可访问管理端 |

### 2.4 统一规范（需求约束）

#### 响应格式

```json
{
  "code": 0,
  "msg": "success",
  "data": {},
  "traceId": "a1b2c3d4"
}
```

#### 错误码约定

| code | 含义 |
|------|------|
| 0 | 成功 |
| 401 | 未认证 |
| 403 | 无权限 |
| 429 | 限流 |
| 500 | 系统异常 |
| 10001+ | 业务错误（用户已存在、签名失败、未开通等） |

#### 开放调用请求头

| Header | 说明 |
|--------|------|
| X-App-Id | 应用标识 |
| X-Timestamp | 毫秒时间戳 |
| X-Nonce | 随机串（防重放） |
| X-Sign | HMAC-SHA256(secret, appId+timestamp+nonce+body) |
| X-Trace-Id | 可选；网关可自动生成 |

## 3. 现状与已完成骨架

当前仓库已完成多模块骨架，可在此基础上继续开发：

```text
ApiHub/
├── api-common/       # 统一返回体、错误码、常量
├── api-gateway/      # 8080  TraceId、路由配置、健康检查
├── api-auth/         # 8081  认证服务骨架
├── api-admin/        # 8082  管理服务骨架
├── api-invoke/       # 8083  开放业务演示（天气）
├── web-admin/        # 前端占位
├── sql/init.sql      # 核心表结构
├── nginx/nginx.conf
└── docker-compose.yml
```

| 服务 | 端口 | 职责 |
|------|------|------|
| api-gateway | 8080 | 统一入口、鉴权、限流、路由 |
| api-auth | 8081 | 登录注册、JWT、角色权限 |
| api-admin | 8082 | 接口/应用/权限/统计管理 |
| api-invoke | 8083 | 模拟企业业务接口 |
| web-admin | 80（Nginx） | 管理后台 |

## 4. 后续开发方向

### 4.1 阶段一（P0 · 必须完成，保证答辩可演示）

**目标：打通「注册登录 → 发布接口 → 创建应用 → 签名调用 → 查日志」主流程。**

1. **认证闭环**
   - 实现注册、登录、注销、`/me`
   - JWT 签发与校验；密码 BCrypt
   - 恢复 MySQL 持久化（去掉骨架阶段的数据源排除）

2. **管理能力**
   - 接口 CRUD、上下线
   - 应用创建、禁用
   - 应用开通接口

3. **网关核心**
   - `/api/auth/**`、`/api/admin/**`、`/api/open/**` 反向代理
   - 管理路由校验 JWT
   - 开放路由校验 App 签名 + 开通关系
   - 写入 `api_invoke_log`

4. **文档与前端最小集**
   - SpringDoc 可访问
   - 前端：登录、接口列表、应用管理、简单调用日志

5. **部署说明**
   - `sql/init.sql` 初始化
   - docker-compose 至少拉起 MySQL + Redis；服务可本地或容器运行
   - Nginx 配置可演示前后端分离

**验收标准**

- 管理员能上线天气接口
- 用户能创建 App 并开通该接口
- 带正确签名调用 `/api/open/weather` 成功；错误签名被拒绝
- 能按 TraceId 查到一条调用日志

### 4.2 阶段二（P1 · 加分与完整度）

1. Redis 限流（QPS）与日调用配额
2. 调用统计概览、近 N 日趋势图
3. 短信 / 翻译等更多演示接口
4. Token 黑名单、Nonce 防重放完善
5. 接口元数据缓存
6. docker-compose 纳入全部后端服务镜像

### 4.3 阶段三（P2 · 可选拓展）

1. 提供 Java 调用方 SDK（封装签名）
2. 在线接口调试台
3. Nacos 注册发现 / Sentinel 熔断（体现更完整微服务）
4. SkyWalking 或 ELK 级链路与日志（了解即可）
5. 接口计费、套餐模型

### 4.4 建议开发顺序（执行清单）

| 顺序 | 任务 | 对应模块 | 产出 |
|------|------|----------|------|
| 1 | 用户表 CRUD + 注册登录 JWT | api-auth | 能拿到 Token |
| 2 | 网关 JWT 校验并转发 auth/admin | api-gateway | 管理端经网关可访问 |
| 3 | 接口与应用表业务实现 | api-admin | 管理 API 可用 |
| 4 | App 签名鉴权 + 转发 open | api-gateway + api-invoke | 开放调用打通 |
| 5 | 调用日志落库与查询 | gateway + admin | 审计可查 |
| 6 | 管理前端主流程页面 | web-admin | 可视化演示 |
| 7 | 限流配额与统计图表 | gateway + admin + web | 加分项 |
| 8 | Docker / Nginx 完整部署文档 | 部署 | 报告部署章节 |

## 5. 接口设计方向（下一迭代对照）

> 对外统一经网关，前缀 `/api`。

### 5.1 认证 api-auth

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/auth/register` | 无 | 注册 |
| POST | `/api/auth/login` | 无 | 登录返回 JWT |
| POST | `/api/auth/logout` | JWT | 注销 |
| GET | `/api/auth/me` | JWT | 当前用户 |

### 5.2 管理 api-admin

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| GET/POST/PUT/DELETE | `/api/admin/interfaces` | USER+/ADMIN | 接口资产 |
| PUT | `/api/admin/interfaces/{id}/status` | ADMIN | 上下线 |
| GET/POST | `/api/admin/apps` | USER+ | 应用 |
| POST/DELETE | `/api/admin/apps/{appId}/grant...` | USER+ | 开通关系 |
| GET | `/api/admin/logs` | USER+ | 调用日志 |
| GET | `/api/admin/stats/**` | USER+ | 统计 |

### 5.3 开放 api-invoke

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/open/weather` | AppSign | 天气 |
| POST | `/api/open/sms/send` | AppSign | 短信模拟 |
| POST | `/api/open/translate` | AppSign | 翻译模拟 |

## 6. 风险与注意点

1. **环境**：若 Windows 版本过旧，Docker Desktop 可能不可用，可改用 WSL 内安装 Docker Engine，或本地安装 MySQL/Redis。
2. **安全**：课程演示可用固定 JWT Secret；正式环境必须外置且足够长。
3. **范围控制**：优先保证 P0 主流程可演示，再做限流、图表、SDK，避免摊子过大无法答辩。
4. **数据源**：进入阶段一时，需去掉 auth/admin 中 `DataSourceAutoConfiguration` 排除，并保证 `sql/init.sql` 已执行。

## 7. 总结

本项目需求围绕「统一接入、双通道鉴权、可审计、可部署」展开。当前已完成多模块工程骨架与库表设计；后续开发应按 **P0 主流程 → P1 增强 → P2 拓展** 推进，确保课程设计既有完整架构表述，也有可运行、可演示的实现结果。
